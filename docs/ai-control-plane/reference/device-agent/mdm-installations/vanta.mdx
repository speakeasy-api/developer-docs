Vanta is an evidence destination, not an MDM: once an MDM inventory source (Jamf Pro or Iru) is connected, the platform pushes one resource per managed device into a Vanta **private integration** on a schedule, and a Custom Test over those resources turns real agent coverage into continuously-tested compliance evidence. Shared concepts — the coverage model and what the evidence attests — are on the [MDM installations](/docs/ai-control-plane/reference/device-agent/mdm-installations) page.

## 1. Create a scope-limited private integration

In the Vanta **Developer Console**, create a private integration (OAuth application) for this integration and grant it only the **`connectors.self:write-resource`** scope — writing its own resources is all it needs.

<Callout type="warning">
  Dedicate this OAuth application to the Speakeasy integration. Vanta allows **one active access token per application** — every new token mint revokes the previous one — so sharing the application with a script or another tool causes the two consumers to continually revoke each other. The integration absorbs a single mid-push revocation gracefully, but a shared application will produce intermittent sync failures.
</Callout>

Copy the **client ID** and **client secret**; both are entered together in the dashboard and stored write-only.

## 2. Define the Custom Resource

In the integration's **Resources** tab, define a Custom Resource for device coverage with this schema (base fields at the top level, evidence fields as custom properties):

| Custom property | Type | Meaning |
| --- | --- | --- |
| `serial_number` | string | Hardware serial from the MDM |
| `hostname` | string | Device name from the MDM |
| `assigned_user_email` | string | The MDM-assigned user (empty when unassigned) |
| `assigned_user_agent_active` | boolean | Whether that user has a recent agent heartbeat |
| `assigned_user_agent_last_seen_at` | string | The user's latest heartbeat; omitted when they have never reported one |

Copy the **resource id** from the resource definition — the third and final value the dashboard needs.

## 3. Connect in the dashboard

1. Open **Device Agent → MDM Integrations**, then **Connect** on the Vanta row.
2. Enter the **OAuth client ID**, **client secret**, and **Custom Resource ID**. Credentials are stored encrypted and are never shown again after saving.
3. **Save**, then **Test connection** — the test mints a token, validating the OAuth credentials and scope. It cannot validate the resource id (the write-only scope has no read to probe with), so a typo there surfaces as a failed first sync instead.
4. Enable the connection. New connections start paused: the flow is save, test, then enable.

Once enabled, evidence pushes hourly as a **full-state sync**: each push is the complete device set, departed devices are marked gone automatically, an empty fleet truthfully clears stale evidence, and retries cannot duplicate (Vanta upserts by `uniqueId`).

## 4. Define the Custom Test

Create a Custom Test over the resource — for example, *fail when any resource has `assigned_user_agent_active` = false* — and map it to the relevant SOC 2 / ISO controls. One stale device fails the test and routes to an owner.

<Callout type="info">
  Agent presence is attested **per assigned user, not per device**: the property names say exactly that, and `assigned_user_agent_last_seen_at` is omitted for a user who has never reported a heartbeat rather than sent as null or a zero timestamp. Phrase the Custom Test over these properties — the integration deliberately never claims "device monitored".
</Callout>
