Logging Settings control what the platform captures from instrumented agents, from tool-call traces to agent session transcripts. Everything in the [Observability section](/docs/ai-control-plane/observe) is powered by these switches. Open them from **Organization settings > Settings > Logging & Telemetry** in the dashboard; the page itself is titled **Logs**.

## Access requirements

<Callout type="info">
  Viewing this page requires the `org:read` scope, so both default Admin and
  Member roles can see current settings. Changing any toggle requires the
  `org:admin` scope, which only the [default Admin
  role](/docs/ai-control-plane/org-admin/roles-and-permissions) holds. Members
  without that scope see the switches rendered but disabled.
</Callout>

## Data retention

Tool logs and agent sessions are retained for 90 days, then age out automatically; a banner at the top of the page states the retention period. See [platform security](/docs/ai-control-plane/reference/platform-security) for how that data is stored and isolated.

## Logging toggles

The page presents a set of toggle rows that control what the platform records. The **Enable logging** step of the setup board (see [getting started](/docs/ai-control-plane/getting-started)) turns on **Enable Logs**, **Record Tool I/O**, and **Agent Session Capture** at once. New organizations start with **Enable Logs** on; every other setting except **Upload Skill Content** is off until an admin turns it on.

- **Enable Logs** records tool-call traces and telemetry. This is the master switch for the settings below it.
- **Upload Skill Content** uploads each skill's SKILL.md content at activation so captured skills can be inspected. When disabled, the platform receives only skill names, source details, hashes, users, and hostnames at activation. This row appears only when skills are enabled for the organization, and it is on by default. The same toggle also appears in [Skill capture settings](/docs/ai-control-plane/org-admin/skills), and the two stay in sync.
- **Record Tool I/O** stores the inputs and outputs of tool calls. Stored payloads may expose sensitive data, so enable it deliberately.
- **Agent Session Capture** captures user prompts and assistant responses from supported coding agents. Captured sessions appear in [Agent Sessions](/docs/ai-control-plane/observe/agent-sessions). The toggle applies to every instrumented agent, including ones without an OpenTelemetry exporter such as OpenCode and OpenClaw, whose transcripts arrive through the observability plugin instead.
- **Fail Open During Outages** lets tool calls proceed when the platform is unreachable instead of blocking them (blocking is the default). Tool calls then only ever block when a blocking policy fires, so with no blocking policies nothing blocks (this was formerly called Observability Mode). Blocking policies go unenforced during the outage; events are still recorded and scanned after recovery, and invalid credentials always block. Flipping this setting is recorded in [Audit Logs](/docs/ai-control-plane/org-admin/audit-logs).
- **Hook Browser Sign-In** lets hook plugins sign users in through the browser so events record under their own identity. When off, plugins use the organization key or explicitly configured credentials.

### How Enable Logs cascades

**Record Tool I/O** and **Agent Session Capture** both depend on **Enable Logs**:

- Turning **Enable Logs** off also turns **Record Tool I/O** off.
- While **Enable Logs** is off, both switches are frozen at their stored value and cannot be changed. Turn logs back on to edit them.

**Upload Skill Content**, **Fail Open During Outages**, and **Hook Browser Sign-In** are independent of **Enable Logs**.

<Callout type="info">
  Settings save immediately, one switch at a time, and the rest of the page is
  locked while a change is in flight. If a save fails, the switch reverts to its
  stored value and an error appears.
</Callout>

## Related settings

- [Data export](/docs/ai-control-plane/observe/opentelemetry) sends normalized OTLP logs, metrics, and traces from each project to an external collector.
- [AI Integrations](/docs/ai-control-plane/org-admin/ai-integrations) connects provider compliance and admin APIs for LiteLLM, Cursor, Anthropic, and OpenAI on its own settings page. Those integrations are optional; the platform works with basic instrumentation alone.

## Used by

- [Tool Logs](/docs/ai-control-plane/observe/tool-logs) and [MCP Insights](/docs/ai-control-plane/observe/mcp-and-tools), which need **Enable Logs**
- [Agent Sessions](/docs/ai-control-plane/observe/agent-sessions) and [Costs](/docs/ai-control-plane/observe/costs), which need **Agent Session Capture**
- [Skills](/docs/ai-control-plane/mcp-gateway/skills), which show SKILL.md content only with **Upload Skill Content**
- [Guardrails](/docs/ai-control-plane/secure/guardrails), whose outage behavior follows **Fail Open During Outages**
- [Plugins](/docs/ai-control-plane/mcp-gateway/plugins) and the [Device Agent](/docs/ai-control-plane/reference/device-agent), which honor **Hook Browser Sign-In**
